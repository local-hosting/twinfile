# RFC 0002 — OCI unit packaging

Status: Accepted (bootstrap 1.0.0-draft.1)
Created: 2026-11-04

## Summary

Published Twinfile **units** ship as OCI artifacts with a typed config blob and one deterministic gzip tar tree layer.

## Motivation

Places, events, situations, and scenarios need registry pins (`Twinfile.lock`) compatible with existing OCI tooling and digests.

## Specification

- `artifactType`: `application/vnd.twinfile.unit.v1`
- Config: `application/vnd.twinfile.config.v1+json` validated by `schemas/1/oci/oci-cfg.schema.json`
- Tree layer: `application/vnd.twinfile.tree.v1.tar+gzip`; annotation `org.twinfile.tree` holds tree digest
- Ref grammar and tags: `doc/pack/refs.md`, `doc/pack/oci.md`
- Default registry for short refs: `ghcr.io` (configurable in implementations)

## Conformance

Future `conf/refs/` vectors for ref parse, floating tags, tar bytes, and tree digest mismatch. Implementations MUST verify manifest and tree digests when pinned.

## Drawbacks

Signing (Sigstore/Notation) is out of scope for v1 normative text.

## Alternatives

Git-only distribution without OCI (rejected for lockfile and registry ergonomics).
