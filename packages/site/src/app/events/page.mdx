# Events and scenarios

A place describes the site. An event describes a story any place can bind. A scenario runs that story against one place. {{ className: 'lead' }}

Unit kinds are `place`, `event`, and `scenario`. A scenario copies the events it plays (arena ships `arena-game-day`).

## Shared events {{ anchor: false }}

Fourteen shared event units ship in the private [`@local-hosting/twinfile/simulator`](https://github.com/twinfile/simulator) catalog. A place opts in through the role tags it carries or a local plan. The event declares `phases` and the roles it `expects`. Hazard label → unit mapping: [`hazard-catalog.yaml`](https://github.com/twinfile/spec/blob/main/conf/hazard-catalog.yaml). Lantern-style map pins: [`hr-marker-crosswalk.yaml`](https://github.com/twinfile/spec/blob/main/conf/hr-marker-crosswalk.yaml).

`twinfile/severe-weather:1.0.0`:

```yaml
twinfile: 1
kind: event
name: severe-weather
version: 1.0.0
stability: stable
phases:
  - watch
  - warning
  - all-clear
expects:
  shelter:
    kind: space
    min: 1
  exit:
    kind: opening
    min: 2
  outdoor:
    kind: space
    min: 0
```

| Event | Expects (excerpt) | Example places |
| --- | --- | --- |
| `severe-weather` | `shelter`, `exit`, `outdoor` | shop, arena, expo |
| `flood` | `flood-refuge`, `safe-access`, `gauge` | tagged places (sites, linear water) |
| `earthquake` | `shelter`, `exit`, `outdoor` | tagged places |
| `wildfire` | `shelter`, `exit`, `safe-access` | tagged places |
| `tsunami` | `flood-refuge`, `safe-access`, `water-launch` | tagged places (coastal) |
| `volcanic-ash` | `shelter`, `exit`, `survey-station` | tagged places |
| `slope-movement` | `safe-access`, `flood-refuge`, `survey-station` | tagged places (avalanche, landslide, lahar) |
| `drought` | `gauge`, `collection-point`, `shelter` | tagged places |
| `power-outage` | `shelter`, `safe-access`, `alternative` | tagged places |
| `dam-release` | `water-launch`, `flood-refuge`, `gauge` | river |
| `transit-disruption` | `ground-transport`, `alternative` | shop, airport, expo, transit-hub-campus |
| `field-damage` | `hotspot`, `safe-access`, `collection-point` | tagged places (debris, closures, structural damage) |
| `litter-pollution` | `hotspot`, `safe-access`, `collection-point` | port, park |

Your `bindings/*.yaml` maps those role names to space and opening ids on this site. See [Author a place](/author#plans).

**Relief vertical slice:** [`twinfile/arena:1.2.0`](https://github.com/twinfile/twinfile/blob/main/examples/arena/) with declarative `ext.shelter_resource` on concourse assets and scenario `flood-shelter-standup` (shelter capacity vs stock on the built place).

## Live controls vs offline runs {{ anchor: false }}

On a built **place**, `image.meta.placeType.controls` is the button surface (`signal:trigger` / event pulses). Prefer that in product UI — not a separate Twinfile per button. The host **player** advances **`clock:`** and publishes the same IN messages as those buttons (patch module bus). **`use.runner`** stays the offline **ENTRYPOINT** for `twin run`, frozen verify, and **`question:`** answers (JSON Lines stdout) — same timeline, different sink ([world time](https://github.com/twinfile/spec/blob/main/doc/glossary.md#world-time-clock-timeline-player-runner)).

## A scene run {{ anchor: false }}

A run is an inline **`run:`** on a scene in a **story** head. `from:` defaults to the story's involves place. `steps[].copy` pulls event units (use typed refs). `args:` are the run inputs. Optional **`use.runner`** is only for offline `twin run`, not live play.

The `shelter-at-cap` scene in `story/examples/shop-visit/shop-visit.twin.yaml` (shop's only reference run):

```yaml
- id: shelter-at-cap
  label: Shelter at capacity
  run:
    steps:
      - copy: twinfile/event/severe-weather:1.0.0
    clock:
      starts_at: 2026-06-12T18:00:00-07:00
      duration: PT30M
      step: PT5M
    args:
      occupancy: 180
      target_role: shelter
```

```bash
twin run story/examples/shop-visit#shelter-at-cap
```

Compose order is place, then events, plan bindings, scenario patches, and `args:` ([composition](https://github.com/twinfile/spec/blob/main/doc/build/composition.md)).
